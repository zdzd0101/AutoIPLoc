## Changes in this pass

1. **Wi-Fi configuration validation**
   - Validate each stored network as a dictionary with string `SSID` and `BSSID` fields.
   - Enforce an SSID length of 1–32 UTF-8 bytes, a six-octet hexadecimal BSSID, and a maximum of 64 entries.
   - Reject the entire malformed list instead of allowing an invalid element to reach Objective-C subscripting or string/data conversion.
   - Validation does not generate, repair, randomize, or normalize identifiers.

2. **ifaddrs allocation ownership**
   - Move only clone-allocation and registry lifecycle bookkeeping into `Tweak/AutoIPLocIfaddrs.c`.
   - The existing `IsVirtualVPNInterface` selection predicate and the call sites that decide which nodes are selected remain unchanged.
   - The helper copies node structures, preserves the original list, registers the clone head, and calls the supplied original-free function exactly once when the registered head is released.
   - Add pre-call null validation for `getifaddrs` output pointer.
   - CI exercises invalid inputs, original-list preservation, ordering, multiple outstanding allocations, duplicate release, and concurrent register/release under AddressSanitizer and UndefinedBehaviorSanitizer.

3. **AVFoundation**
   - No AVFoundation, AVAudio, AVCapture, or AVPlayer API use was found in the app source.
   - Remove the unused import and link dependency.
   - Remove the unused `audio` background mode; retain `location`.
   - This does not claim that background location or private location simulation is supported on every device or iOS version.

4. **CI regression coverage**
   - Run real C ownership tests and Swift Wi-Fi schema tests.
   - Keep the existing iOS SDK, arm64/arm64e, platform metadata, signing, and package checks.

## Audited behaviors intentionally left unchanged

These behaviors were not deleted, expanded, re-written, or calibrated in this pass. They remain risks and may conflict with one another or with ordinary app/system behavior.

| Area | Current behavior observed | Potential conflict / audit result |
|---|---|---|
| Jailbreak and dylib identity | Path checks, dyld image-name replacement, `dladdr` rewriting, environment-variable masking, and file API interception | Different APIs can report different filesystem or image states; can break legitimate diagnostics, package tools, and software that depends on truthful paths. |
| URL scheme checks | Selected schemes (including package-manager and VPN-related schemes) are reported unavailable | App launch discovery, deep links, and URL capability checks can fail even when the target app is installed. |
| Proxy reporting | CFNetwork/SystemConfiguration proxy hooks can return a cleaned dictionary, while a caller exception may return the original; NSURLSession configuration returns an empty dictionary | Consumers using different APIs can disagree about proxy state. No attempt was made to make these reports more consistent. |
| Interface enumeration | `getifaddrs` excludes names matching the existing virtual-interface prefix predicate | Network clients and system components enumerating interfaces may observe a list that differs from the kernel/system view. The predicate was not changed. |
| Location-source metadata | Location and source-information hooks report software simulation as false while the app calls the private simulation manager | The reported source metadata can contradict the actual origin of the coordinate; consumers relying on this metadata may behave unexpectedly. |
| Carrier and geography | Carrier/MCC/MNC/radio fallbacks are fixed independently of the GeoProfile country/timezone fields | Telephony, country, IP-geolocation, and timezone surfaces can disagree. No identity alignment or new fallback was added. |
| Wi-Fi dictionary | The returned dictionary includes the standard CaptiveNetwork keys and also custom `NearbyAP1` / `NearbyAP2` entries | The custom entries are not part of the documented CaptiveNetwork key set and have no in-repository consumer; third-party consumers may ignore them. They were left unchanged. |
| Hook status | A recent hook report indicates that a process produced a report, not that every target process loaded every hook | UI status must not be interpreted as proof of device-wide activation. |

## Not established by CI

- CI does not prove that a real iPhone has loaded the tweak or that CoreLocation private APIs work on a particular iOS build.
- No real-device install, upgrade, rollback, uninstall, location, network, or long-duration stability test is performed by these host-side tests.
- The multi-`.jbroot` install-path ambiguity and the previously documented cross-process container/file-access limitations remain unresolved.
- The presence of a passing CI run is not a device acceptance result.

## 2026-11-27 — real-device feedback follow-up

The user reported that IP location did not appear, Hook status remained "target process unverified", and IP time-zone following did not behave as expected.

### Addressed in the follow-up candidate

- Reverse-geocoding UI updates were gated on `isSimulating == true`; an unavailable private location-simulation manager could therefore discard an otherwise valid geocoding result. The callback now uses the request-generation guard only.
- The UI did not independently expose provider city/region and unmodified IP-coordinate estimates. A separate read-only `IPGeoDisplayInfo` parser and display path show those facts without feeding them to the private location manager.
- Automatic IP information refresh now reacts to active interface signature changes (Wi-Fi/cellular/Ethernet), not only changes in `NWPath.Status`. The refresh path is display-only.
- IP timezone is displayed as a provider estimate and compared with the current device timezone. The UI explicitly states that this does not change the device-wide iOS timezone.
- Hook status now reports the last reporting process and C/Objective-C hook counts while retaining an unverified state for other target processes. One process report is not presented as device-wide proof.
- FreeIPAPI uses the documented free API host/path. Multiple possible timezone values are not reduced to an arbitrary first choice.

### Boundaries and remaining acceptance

- Existing private location simulation, VPN/interface, jailbreak, proxy, carrier, and simulation-source hooks were not enhanced by this follow-up.
- The IP geodata path is for factual display only; it does not synthesize device location, change system timezone, or reconcile network/telephony identity.
- CI cannot establish device-wide Hook injection, private API compatibility, OS-level timezone changes, or physical-device stability.
- Validate the build on iPhone 11 Pro / iOS 16.2. Keep PR #1 Draft until device validation is complete.
